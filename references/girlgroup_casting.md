# 多人阵容选角：两层锁定法（girlgroup-casting 蒸馏）

> 吸收自 girlgroup-casting skill v1.0.0（prismhz_photo 仓库，棱镜Hz 四人女团实战）· 2026-10-11（只学不装）。
> 用途：为一支**多人团体**（2–7 人，女团/男团/乐队/剧团/虚拟艺人组合）建立面部资产库——多人不撞型，单人可迭代。
> 完整活样例（4 人 × 16 区块）：`girlgroup_casting_example.md`（棱镜Hz）。
> 单角色流程不变（主流程第 0~6 步）；**多人阵容在本 skill 中作为团体选角模式**，挂接在成组出图防模板化之前。

## 〇、两种多人场景（先判断走哪条路，2026-10-11 实战补入）

| | **同团模式**（本文件 §一~六） | **独立组模式**（A/B 双组实战提炼） |
|---|---|---|
| 用户说 | 「设计一支女团/组合」「全员统一风格」 | 「设计 N 个风格完全不同、性格完全不同的角色」 |
| 统一什么 | 妆容母版 + 摄影规格（固定层） | **画风**（默认电影级真实感/真人/现代人）+ 定妆规范（灰底 3:4） |
| 差异化在哪 | 可变层（四项铁律四选三） | **四大阵营各占一**（皮×神四象限互斥：洞察者/造梦者/抚慰者/凌越者），细格（骨×形）再互异 |
| 妆容路线 | 全员一致（母版不得稀释） | **每人独立**（realism/refined/standard 按人设分配） |
| 锚点纪律 | 库内不重复 | **跨组查重**：N 个角色锚点位置/类型全不重（如疤/泪痣/雀斑痣/眉钉四类四位置） |
| 产物 | 面部资产 → 三视图 → MV（三道门） | 每人独立走三级产物链（肖像 → 肖像三视图 → 无头全身三视图） |
| 活样例 | `girlgroup_casting_example.md`（棱镜Hz） | `casting_ab_example.md`（A 组摄影师/歌手/护士/电竞 + B 组艺人四型） |

**判断口诀**：用户要「一支团」走同团（统一母版）；用户要「几个人风格完全不同」走独立组（统一画笔、人各一面）。两者都遵守：锚点查重、单变量返修、出图后主动撞型检测。

## 一、两层锁定法（核心方法论）

把「稳定妆容与摄影质感」和「可变化的人物身份」分成两层分开控制：

**固定层（妆容母版，全员一致，不得被稀释）**——以韩系女团定妆照为例：

| 区块 | 母版内容（女团示例，按场景替换） |
|---|---|
| 皮肤基调 | 冷白粉瓷肌 + 真实细微皮肤纹理 |
| 妆容系统 | 韩系粉调（奶油粉/草莓牛奶粉/灰粉/浅玫瑰粉眼妆；下眼睑粉妆、自然卧蚕、空气感分束睫毛） |
| 腮红 | 眼下至苹果肌上缘连续的透明冷粉腮红 |
| 唇 | 果冻唇：粉润鲜活、中央渐层、下唇中央透明高光 |
| 整体质感 | 商业美妆级：高明度、低至中等饱和度、柔和低反差 |
| 摄影规格 | 纯白背景、贝壳光（上方大柔光箱 + 下方白色反光板）、平视中长焦、无广角畸变 |

**可变层（身份区隔，每人独立设定）**：

- 脸型轮廓与面部长度
- 眉眼形态、双眼皮结构与眼尾方向
- 鼻梁、鼻尖、鼻翼关系
- 唇宽、唇峰、上下唇比例与静态表情
- 发际线、刘海、发长、发型轮廓、发色
- 一至两个不突兀的身份记忆点（痣、耳环、雀斑等）
- 服装领口可见部分与成员气质

**为什么分两层**：固定层保证「同一支团」的视觉统一与出图稳定性（母版句逐字复用，不被各成员描述稀释）；可变层保证「不同的人」。混在一起写，两头都做不好——与脸型库「风格层/身份层分离」同构，但粒度是**团 → 成员**。

> 与 `structure_and_makeup.md` §5「同妆不同脸」的关系：南鸢六组计数管**差异够不够**（计数维度），两层锁定法管**怎么组织提示词**（母版复用 + 身份注入），配合使用：先写母版，再按六组计数给每人注入可变层。

## 二、四项差异化铁律 + 高审美底线

**铁律**：不同成员至少在「**脸型轮廓、眉眼形态、鼻唇比例、发型与发际线**」四项中的**三项**明显不同。不得只换发色或衣服；**不得用降低颜值的方式制造差异**（宽大失衡鼻形、凹陷面中、突兀下颌都是错的差异化）。短发成员超过一人时尤其警惕发型撞型。

**高审美底线（每个成员提示词必备区块）**：人物漂亮、精致、上镜，具有商业定妆照的完成度；五官协调、面中舒展、鼻唇关系自然；**不生成平庸路人脸、统一网红模板脸或过度幼态娃娃脸**；**不参考、不复刻任何现实艺人**。

> 这条底线是「防差异化跑偏」的护栏：差异化做在正常美的分布里，而不是做丑。出图后撞型检测发现两人过近 → 只改其中一人的可变层，固定层不动。

## 三、16 区块提示词骨架（面部资产照，每人一条）

```
1  开场定位      单人面部资产照，竖幅；年龄/族裔/气质核心；「她与其他成员的身份差异」一段点明
2  人物五官      脸型 → 眉眼 → 鼻 → 唇 → 身份记忆点（可变层，逐人不同）
3  高审美底线    防差异化跑偏 + 不复刻现实艺人
4  皮肤与底妆    （固定层母版）
5  眉妆          服从人物眉形（母版质感 + 可变眉形）
6  眼影与下眼睑粉妆（固定层母版）
7  卧蚕、眼线与睫毛（固定层母版；眼线走向服从人物眼型）
8  虹膜与眼神    虹膜色 + 眼神气质（可变层）
9  腮红与鼻部    （固定层母版）
10 果冻唇        （固定层母版）
11 发型          （可变层：发长/轮廓/分缝/发色/碎发）
12 服装          仅可见肩颈与领口，无图案文字品牌，不抢面部
13 构图          头肩近景正面平视，头顶至锁骨下方，无手部，无多人/拼图/三视图
14 背景、光线与色彩（固定层：纯白背景 + 贝壳光）
15 质感与清晰度  真实摄影质感清单 + 整头同一焦平面 + 反 3D/动漫/蜡像
16 负面控制      逐人定制：锁死该成员的发型发色、脸型、眼型、鼻唇的反向清单
```

> 区块 1 里「她与团队其他成员的不同身份差异」一句是**防稀释关键**：明确告诉模型这个人在阵容里的区隔点，比单写特征更能防撞型。
> 区块 16 逐人定制——每人的负面清单写**与该人设定冲突**的方向（如 Hz-01 清冷垂眼 → 负面写下挑眼、攻击性高鼻）。

## 四、主题色体系（多人团管理）

为每位成员分配主题色（呼应团名概念），写入服装与配饰色：

| 成员 | 定位 | 主题色 | 概念 |
|---|---|---|---|
| 棱镜Hz 示例 | 主唱/领舞/门面/忙内 | 月光银白 `#DDE0EA` / 琥珀金 `#F0A830` / 蜜桃粉 `#F2A6A0` / 薰衣草紫 `#B4A0E5` | 白光过棱镜分四束光 |

应用：MV 造型主色与打光色卡、应援色、专辑概念视觉、团综包装。团色统一时个人色出现在袖标/耳返/鞋带等细节。**主题色是「团概念 → 成员气质 → 造型」的翻译器**，没有团概念的团也建议补一层（哪怕只是色相分配）。

## 五、确认门机制（流程控制）

```
第一道门：全员面部资产提示词 → 批量出图 → 用户逐人验收
第二道门：面部锁定后才进人物三视图（16:9 一行多格设定板，锁头身比与团服）
第三道门：三视图确认后才进 MV / 舞台视频提示词
```

- 未过门不进入下一阶段；**返修只重掷被否决的成员，不全员重跑**。
- 与主流程第 5.5 步「用户确认提示词」同源，扩展为**多阶段门控**：单人流程是一扇门，团体流程是三扇门。
- 三视图格式：16:9 一行多格（正/侧/背 + 面部特写），一次性锁身体比例与舞台服装。

## 六、迭代返修模式

| 场景 | 做法 |
|---|---|
| **撞型检测** | 出图后**主动**横向对比全员（不等用户发现），两人发型/脸型过近 → 只改其中一人的可变层，固定层不动 |
| **气质微调** | 用户要「更幼态/更成熟」→ 调妆容母版的腮红位置、卧蚕强度与眼神词，**不动骨相** |
| **单变量原则** | 每次返修只修一个变量（脸型或眉眼或发色），**不连坐** |
| **回滚** | 迭代不如初版时回滚，git 式命名（v2/v3 后缀）保留全部版本图 |
| **单张重掷** | 只重跑问题成员，用完整提示词原文投喂，不改其他成员 |

> 与南鸢「点名式修改协议」的关系：同一条血脉（最小修改、不写「其它同上」、交付完整新稿）；本表补了**回滚**与**单张重掷**两个工程动作。

## 七、多参考图职责（图生图锁脸时）

同时提供多张参考图时，为每张分配**唯一职责**并写进提示词开头：

| 参考图 | 只锁 | 不继承 |
|---|---|---|
| 人脸参考 | 脸型骨相、眉眼、鼻唇比例、身份记忆点 | 发型、服装、摄影 |
| 发型参考 | 发长、轮廓、刘海、发色 | 该图的脸 |
| 服装参考 | 品类、剪裁、材质、配色 | 脸与发型 |
| 摄影参考 | 布光、色调、景别、质感 | 人物身份 |

**参考冲突时，以已确认的面部资产为准，其余参考不得覆盖。** 与 `prompt_craft.md` §12 图生图锁脸模板配合：§12 管七段骨架怎么写，本节管多张参考图怎么分职责。

## 八、出图链路（RunningHub G-2，批量出图主力通道）

主通道是 `generate.py --generate`（OpenAI gpt-image-2）；**批量出多人定妆照**时主力通道：RunningHub `rhart-image-g-2/text-to-image`（3:4、1k、2 并发），下载后做 **PNG 完整性双重校验**：

1. 尾部 12 字节 hex 必须等于 `0000000049454e44ae426082`（IEND 块）
2. 文件大小与响应 Content-Length 一致

校验失败 → 用 taskId 重新查询 resultUrl 补下载。

**2026-10-11 全链路实测记录**（A+B 两组 8 人定妆肖像，2 并发）：
- 8/8 成功，总耗时约 5 分钟，PNG 校验全过；单张约 ¥0.015（价格会变，以账户为准）。
- **中文提示词直投可行**：每张 730–790 字的完整中文定妆提示词（含【肖像设定】【构图与比例】等段落标记）直投无障碍，效果符合预期——不需要先翻译成英文。
- **key 解析链**：`--key` 参数 → 环境变量 `RUNNINGHUB_API_KEY` → OpenClaw 配置（`skills.entries.runninghub.apiKey`）。环境变量没设也能从配置读到；先跑 `--check` 做健康检查（返回 key 来源、余额、运行中任务数）。
- **出图脚本模式**（复用棱镜Hz 的 gen 脚本骨架，已被两次实战验证）：解析设定 md 中的提示词代码块 → 逐人调 CLI（`--endpoint rhart-image-g-2/text-to-image --prompt <全文> --param aspectRatio=3:4 --param resolution=1k -o <输出>`）→ ThreadPoolExecutor 2 并发 → 全部完成后跑 IEND 校验并打印汇总。CLI 位于 `~/.workbuddy/skills/OpenClaw_RH_Skills/scripts/runninghub.py`（仅标准库依赖）。

## 九、边界与防污染

- **两层锁定法不等于全员同妆**：固定层是「本团的母版」，女团示例是韩系粉调妆；做现实主义题材多人阵容时，固定层换成「同一摄影规格 + 同一光线体系」，妆容仍走各自设定——固定的是什么由团的类型决定。
- **16 区块骨架是韩系女团定妆照的产物模板**，与主管线 `generate.py` 三视图骨架、`portrait_3x4.md` 定妆肖像模板**三套不混写**：单角色三视图 / 单人 3:4 定妆 / 多人团面部资产，各走各的。
- **确认门第三道之后的 MV 视频提示词**归 seedance25 系视频 skill 管，本 skill 产出到三视图确认为止。
- **果冻唇/贝壳光等母版词是女团场景词**，不是普适词；realism 路线单人不套用。
- 「不参考、不复刻任何现实艺人」为普适合规句，所有路线保留。
