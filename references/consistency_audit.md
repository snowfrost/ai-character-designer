# 一致性审计与变量主权（MOKE SkillHub 四 skill 蒸馏）

> 吸收自 MOKE SkillHub（mokeaigc.com）本地已装 skill：cross-shot-consistency-audit（跨镜头一致性矩阵审计）、
> entity-continuity-system（实体化资产与连续性数据系统）、invariant-exploration-director（不变量—探索变量导演控制）、
> minimum-visual-bible（最小充分 Visual Bible）· 2026-10-11（只学不装，源均出自 MokeLMa《AI 创作体系》课程蒸馏，三重验证 V1/V2/V3 通过）。
> 定位：**出图前定规则、出图后做验收的治理层**——前面的 reference 管「怎么设计角色、怎么写提示词」，本文件管「怎么锁住不该变的、怎么验收已经出的」。
> 它解决：出图后「感觉不统一 / 像换了个人 / AI 味重」说不清哪里错；批量候选「都正确但僵」或「有惊喜但脸漂了」；「高级感」这类抽象验收标准没法打勾。
> 它不解决：提示词怎么写（走 prompt_standards / clean_rendering）、撞脸设计（走 face_library_220 锚点）、视频分镜连续性（归 seedance25 系 skill）。

## 〇、触发场景

- 单角色多张出图（定妆图→三视图→组照）后，怀疑脸/身材/材质在张间漂移。
- 多人团全员出图后要做**横向验收**（谁撞了、谁飘了、谁要重出）。
- 换装/变体/探索性批量生成，纠结「哪些必须锁死、哪些可以让 AI 自由发挥」。
- 用户只说「不统一」「AI 味太重」「像贴上去的」，需要把感觉转成可定位的差异矩阵。

## 一、跨镜头/跨张一致性审计矩阵（出图后验收）

> 核心原则：一致性不是逐张判断「好不好看」，而是判断「**是否仍属于同一个世界/同一个人**」。
> 审计必须**先指定获批锚点**——没有锚点只能得到互相之间的差异，无法判定谁在漂移。

### 1. 审计前置

- 把要审的图按用途排好序（定妆图 → 三视图 → 组照的时间线），同一显示条件下并排（contact sheet）。
- 指定**锚点**：通常是用户已确认的定妆图/角色卡锚点句。锚点代表标准，其它图向它对齐。
- 同时记录**有意变化**（换装、情绪推进、场景转换），避免把设计当缺陷。

### 2. 八维度矩阵（每图 × 每维度打分，不适用标 N/A 不许静默跳过）

| 维度 | 检查项（人像场景版） |
|---|---|
| 身份与状态 | 脸型、骨相三区、五官锚点、发型、身材比例、服装、损伤/污渍、妆面状态 |
| 空间与连续性 | 站位关系、视线方向、左右关系、遮挡、姿态承接 |
| 光照 | 主光方向、软硬、光比、色温、接触阴影、反弹光 |
| 色彩与调性 | 白平衡、曝光、肤色还原、饱和度、主辅色关系 |
| 材质与细节 | 皮肤质感（毛孔/绒毛有无）、布料织纹、发丝分组、粗糙度 |
| 成像与风格 | 写实度一致性、锐度、景深观感、颗粒、有无 AI 伪影 |
| 构图（人像替代运动） | 景别配比是否按 50/30/15/5（成组防模板化）、机位多样性 |
| 品牌/文字（如适用） | 团服 logo、应援色、字号层级 |

### 3. 四级严重度

| 级 | 定义 | 处理 |
|---|---|---|
| **0 匹配** | 与锚点一致 | 通过 |
| **1 有意或可容忍差异** | 有设计依据（换装/情绪/景别） | 标注「为何是有意变化」 |
| **2 可局部修复漂移** | 五官某锚点跑了、光向跳了、材质突变 | 走修复路由，证据要可观察（「S3 的颧骨锚点从高位跑到横向」），不许只写「脸不对」 |
| **3 身份/叙事冲突** | 换人了、比例崩了、风格出世界 | 必须重做，未清零不交付 |

### 4. L1–L4 修复路由（按影响半径最小优先）

- **L1 局部后期**：曝光、白平衡、局部饱和、锐度——能修不重出。
- **L2 定向匹配**：参考锚点图做图生图迁移、局部重绘、状态资产替换（换装变体首选）。
- **L3 约束重建**：身份/比例/锚点错误——回角色卡修字段重新渲染提示词，重出。
- **L4 裁决**：两张图各自都好但放不到一起——交用户决定删/换，不让算法折中平均。

### 5. 回归纪律

修复后**用同一矩阵、同一锚点重新打分**，不得换标准让结果通过；3 级未清零不交付，2 级遗留须用户批准并写明风险。

> **视觉验收分工说明（2026-10-11 实战）**：模型侧若不支持读图，审计矩阵就是**交给用户的人工验收工具**——把矩阵表和严重度定义随图一起交付，让用户按维度打勾，回收后按修复路由执行。不要因为「我看不了图」就跳过验收环节。

## 二、实体三分法（同一角色的数据纪律）

> 核心原则：反复出现的角色不要当「图 1」临时引用，要当**可追踪实体**——但按风险裁剪，不做完整资产管理系统。

| 层 | 回答 | 人像场景内容 |
|---|---|---|
| **身份不变量** | 她是谁 | 骨相三区、五官锚点、脸型、发际线、肤色基调、身材比例——**对应角色卡 `identity_lock.locked` 与 `[识别]` 锚点** |
| **状态** | 此刻怎样 | 当前服装、发型版本、妆容版本、情绪、损伤——**对应换装/剧情推进的可变层** |
| **镜头实例** | 哪版哪个视角 | 定妆图 v3、三视图 v2、组照 05——**对应文件命名与版本号** |

- **名字不是身份锁**：角色名、seed、单张参考只提供线索，不保证跨场景一致——所以才有「同角色换场必走图生图 + 身份块完整重写」铁律（SKILL.md 注意事项），两边同源。
- 每条不变量都要**可观察验收**（「左眉尾有一颗 0.5mm 痣」而不是「保持一致」）——这就是 220 库毫米级锚点的理论根据。
- 状态变化要有依据（换装因剧情、剪发因时间线），无依据的状态漂移就是 2 级污染。
- 小任务轻量记录即可；只有跨项目复用的角色才值得完整三级建档。

## 三、变量主权三档（换装/批量探索前先分权）

> 核心原则：可控与惊喜不是一个总强度滑杆——**先把不同变量分进不同主权区**。
> 「控制 50%、自由 50%」是经验比喻不是配方；比例随返工成本变。

| 档 | 判定规则 | 生成契约写法 | 人像场景例 |
|---|---|---|---|
| **I 不变量** | 偏离会破坏身份/叙事/连续性，或返工代价高 | `MUST KEEP` | 骨相三区、五官锚点、脸型、发色、身高比例 |
| **C 条件变量** | 可在范围内变，越界需批准 | `MAY VARY WITHIN` | 妆容浓淡（同一色系内）、服装款式（同一人设方向内）、表情（气质区间内） |
| **E 探索变量** | 偏离不伤核心，可能带来改善 | `EXPLORE` | 背景环境、光线方案、构图机位、配饰细节 |

**执行纪律**：

1. 生成前先出主权表（宁短勿缺：极小任务三行 `MUST/MAY/EXPLORE` 即可）；信息不足的变量**先按 I 处理**，待用户确认再放开。
2. 一轮只放开 **1–2 个 E 变量**做探索焦点，其余 E 暂时固定——否则出了惊喜没法归因。
3. **验收顺序铁律 I → C → E**：先查不变量，I 挂了直接淘汰不参与「惊艳排名」；I 全过再查 C 越界（越界候选单列为待批准提案）；最后才评价 E 的惊喜是否服务人设。先被惊艳吸引再忽略脸漂，是最常见的错误排序。
4. 失败形态路由：同一 I 反复失败 → 停止扩量，升级证据（换图生图/加参考图/回改角色卡），不是继续掷；结果正确但僵 → 检查是否把低风险变量误列为 I，降级一项为 C/E；惊喜有效 → 提议进角色卡新版本，**经用户批准才落卡**，不静默改标准。

## 四、抽象词转可见契约（验收标准落地）

> 核心原则：只有形容词没有锚点，形不成约束——「高级感」「清冷」「氛围感」必须翻译成可打勾的条款。

每条验收规范写成五件套：

```text
意图（抽象词） → 可观察特征（亮度区间/主光方向/材质响应/构图关系） → 获批正例（锚点图）
→ 禁止反例（什么不算） → 验收人
```

例：「清冷感」→ 哑光皮肤低反射 / 主光高侧位小光比 / 低饱和冷调背景 / 表情收敛不露齿 —— 正例＝定妆图 v2，反例＝高光油亮皮肤+暖调背景，验收人＝王老师。

**合格线**：两个没参与起草的人对同一测试图能得出一致的是否通过结论；做不到就继续具体化。

**代表性镜头试跑**：批量生产前（多人团全员出图前），先出 2–4 张覆盖最高风险的图试跑——主角近景（脸锚点）、全身（比例）、关键情绪（表演）、最复杂材质（净化层）——试跑失败先修标准再放量，不要全量生成后再救。

## 五、与本 skill 的对接（装在哪）

- **单角色流程**：第 5.6 步出图后的「出图后必跑核验」铁律（SKILL.md 注意事项）升级为 §一审计矩阵打分——从「逐项打勾」升级为「维度×严重度×修复路由」。
- **多人阵容模式**：三道确认门的第一道（全员面部资产验收）用 §一矩阵做横向审计（八人八位锚点查重表是出图前设计工具，§一矩阵是出图后验收工具，一前一后）；交付前用 §四把「团概念」类抽象词转成可验收契约。
- **换装/变体探索**（后期变装、多套造型）：先走 §三出主权表（MUST KEEP = identity_lock.locked），再生成；惊喜落卡需用户批准。
- **文件命名与版本**：§二实例层对应现有 `v2/v3 命名保留全版本` 纪律——文件名里带实体+状态+版本，不用「最终版 2」。

## 六、边界与防污染

- **审计不是选片**：从大量候选中挑方案走「bounded-explore-select」思路（生成→评分→收敛），本文件矩阵只审**已入选进入交付序列**的图。
- **没有锚点不判合格**：用户还没确认过任何定妆图时，只能交付差异清单，不判 PASS/FAIL——先回主流程出定妆图。
- **差异 ≠ 错误**：换装、情绪推进、景别变化是有意差异（1 级），不要见差异就返工——审的是「是否仍属于同一个世界/同一个人」。
- **与 seedance25 系 skill 的边界**：视频侧的跨镜头连续性（首末帧、分镜承接、表演连续）归 seedance25-prompt-skill；本文件管**静态图资产链**（定妆→三视图→组照）的一致性。
- **与 casting_ab_example.md 锚点查重表的边界**：查重表管出图前设计（锚点不重复），本文件管出图后验收（矩阵打分）——不要拿查重表去审图，也不要拿矩阵去设计锚点。
- **提示词摄影参数不是物理证据**：提示词里写了 85mm 不代表物理准确——审计依据是画面可见的透视、光照关系，不是提示词里的数字。
- **治理按风险裁剪**：一次性、低返工成本的单角色不需要全矩阵——三行 MUST/MAY/EXPLORE + 锚点对照即可；本文件全套是多人团/跨项目复用角色的装备。
